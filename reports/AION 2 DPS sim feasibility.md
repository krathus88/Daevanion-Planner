# Build the calculator before the simulator

**A full Raidbots-style simulator for AION 2 Global is not feasible today, but a validated gear and Daevanion comparison tool is, and the existing static React/Web Worker stack can run it.** Compute is not the constraint: a browser can run staged Monte Carlo searches, and a closed-form model is cheaper still. Skill inputs are also better than expected, because a fan site publishes client-derived JSON with per-level coefficients, cooldowns and cast times under open CORS. The constraints are knowledge and upkeep. NC has published no damage formula, most tests come from KR/TW clients, nobody has published cancel or animation timing, boss HP and defense are server-side, and Global patches weekly. A rotation sim built on those gaps would produce precise numbers with unknown accuracy. The right product is an expected-damage model calibrated against Global dummy runs, which reports ties when a comparison is too close to call, with a rotation sim added one class at a time only if it passes measured timing tests. Competitors already offer what-if calculators, so visible validation is what would set this one apart. The first step is a one-class calibration on the Global client, before any UI work.

## Almost nothing about the damage model is officially confirmed

The sources fall into five evidence levels, and most English guides sit lower than they appear. **Nearly every English guide seems to derive from one kanonxo-based community model**, so their agreement is not independent confirmation ([MMO Herald](https://www.mmoherald.com/aion-2/guides/damage-calculation)). The strongest independent evidence is Taiwanese and Korean testing from December 2025 to July 2026, on clients with different numbers from Global.

KR values cannot be carried over. Global reportedly has a level cap of 45 against 50, 4 stigma slots against 6, and no Brawler ([DaevaGuides](https://daevaguides.com/en/guides/global-vs-korea/)). Its best-in-slot cooldown reduction is about 19–21% against 34–40% ([Gameplay Tips](https://gameplay.tips/guides/aion-2-spiritmaster-rotation-macros-guide.html)). Most stat values in English guides are KR end-game figures with support buffs, so one guide tells readers to trust the order and not the decimals ([AI Exodus](https://ai-exodus.com/companion/aion/news/how-damage-works-in-aion-2/)).

## Client data covers the inputs, while the formula and timing stay unproven

The inputs are the pleasant surprise. **Aion2Data publishes 68 JSON datasets from the Global client, stamped with client version and Steam build** ([index](https://aion2data.com/raw/index.json)). Its 327 skill records give Rush Strike as `1267 + 125% Attack` at level 10 and `3030 + 125% Attack` at level 40, with a 20,000 ms cooldown and 0 ms cast ([skills.json](https://aion2data.com/raw/skills.json)). That fits the Taiwanese finding that skill level moves only the flat part ([Inven 909](https://www.inven.co.kr/board/aion2/6444/909)), though this is one skill and should be checked across the dataset. It also makes Daevanion skill nodes directly modelable. As an illustration, if Rush Strike's flat value grows linearly (about 59 per level) and Attack is 3,522, a value from a KR test ([Savetip](https://game.savetip.co.kr/aion2-weapon-damage-amplification-test/)), one level adds about 0.8% to that skill before defense. The gain shrinks as Attack grows. The planner's class presets already map abilities to board cells, so a comparison tool can read skill-level nodes from existing project data. Stat nodes need adding from the `daevanion` dataset.

The formula is a different matter. The community skeleton is usable, but its disputes touch stats players actually choose between. Multi-hit is valued at about 0.15–0.16% per 1% in two sources and about 0.33% in a third ([Inven 909](https://www.inven.co.kr/board/aion2/6444/909), [DC Inside](https://gall.dcinside.com/mgallery/board/view/?id=aion2&no=1619125), [AI Exodus](https://ai-exodus.com/companion/aion/news/how-damage-works-in-aion-2/)). Perfect's gain is reported as about 3% at a 100% rate and as 7–9% per Perfect hit ([Inven 902](https://www.inven.co.kr/board/aion2/6444/902), [Inven 23000](https://www.inven.co.kr/board/aion2/6448/23000)). Weapon Damage Boost is about 0.5–0.55% or 0.66% per 1% ([AI Exodus](https://ai-exodus.com/companion/aion/news/how-damage-works-in-aion-2/), [Savetip](https://game.savetip.co.kr/aion2-weapon-damage-amplification-test/)). The best crit-damage formula reports small errors at high stats and a withheld full version with one unresolved variable ([Inven 1431](https://www.inven.co.kr/board/aion2/6444/1431)). Race amp placement conflicts between tests ([Inven 902](https://www.inven.co.kr/board/aion2/6444/902), [Inven 1431](https://www.inven.co.kr/board/aion2/6444/1431)). Even a clean-looking crit-rate fit proves little, since it has three free parameters against three data points.

Timing is the larger gap, and it separates a calculator from a simulator. No dataset checked contains animation lock or minimum cancel time, and `cast` is 0 ms for at least one instant skill. Combat Speed behaves in steps that differ by skill and class: a KR Brawler test logged 810 hits at 117.1 and 860+ at 117.3, about 6% more hits from 0.2 of the stat ([Inven 2147](https://www.inven.co.kr/board/aion2/6444/2147)). Brawler is absent from Global, and no current Global breakpoints were found, though snippets report similar thresholds for Chanter and Assassin. KR also raised cancel delays against macros on 16 Sept 2026 without publishing the values ([AION2 Hub](https://aion2hub.com/updates/aion-2-update-2026-09-16)). Spirit snapshots, stack mechanics and unpublished proc rates add per-class logic with no reliable data behind it ([Gameplay Tips](https://gameplay.tips/guides/aion-2-spiritmaster-rotation-macros-guide.html)).

Target data is also thin. "HP and combat stats are not in the client" ([Aion2Data](https://aion2data.com/raw/index.json)), and no boss defense table was found for any client. Client data does supply enrage timers and boss cast data ([boss-mechanics.json](https://aion2data.com/raw/boss-mechanics.json)). A dummy scenario with user-editable resistance is therefore realistic, whereas boss presets would have to be measured and labelled by build.

## Browser compute is the easy part: 1,000 candidates in about 30 seconds

SimulationCraft has shown the browser is not the limit. A third-party site runs the full SimC engine through WebAssembly ([simc.wow.fipso.dev](https://simc.wow.fipso.dev/)), and WoWSims ships a WASM simulator ([WoWSims](https://github.com/wowsims/wotlk)). A toy event sim in plain JavaScript, run for this research on Node 24 (the same V8 engine as Chrome), reached **26,000–90,000 fights per second per thread**. A real class model will be slower. Assuming 10–100× slower, an unmeasured estimate, gives about 1,000–9,000 fights per second. At 4,500 per worker across 4 workers, Raidbots-style culling of 1,000 candidates at 200, 3,000 and 30,000 iterations ([Raidbots](https://support.raidbots.com/article/55-smart-sim)) takes about 30 seconds, against 28 minutes without culling. Slow phones, throttled hidden tabs and Safari remain real risks ([WebKit, snippet](https://bugs.webkit.org/show_bug.cgi?id=237789)), so runs should be chunked and cancellable. Plain TypeScript in the existing worker pattern looks adequate, with no Go or Rust toolchain needed at first.

The harder comparison is with the prerequisites that made SimC possible. WoW offers patch-exact client extraction and automatic character import, and SimC's per-class logic is still hand-written by volunteers ([SimC wiki](https://raw.githubusercontent.com/wiki/simulationcraft/simc/Participate.md)). Support still slips at prepatches ([Raidbots](https://support.raidbots.com/article/69-why-isnt-my-spec-supported)). AION 2 has fan-derived extraction, no browser-readable import, and one maintainer against 8 classes. Other games show a cheaper route. Guild Wars 2's Discretize optimizer multiplies roughly constant attributes by coefficients solved from logs, and reports that stale coefficients "usually" leave the best gear unchanged ([Discretize](https://raw.githubusercontent.com/discretize/discretize-gear-optimizer/staging/docs/How%20It%20Works.md)). FFXIV tooling rests on a community-derived formula ([Allagan Studies](https://www.akhmorning.com/news/allagan-studies-release/)). SimC's own wiki says a simulation centers on the target with scatter, while a formulation is repeatable but can sit off-center ([SimC wiki](https://github.com/simulationcraft/simc/wiki/FormulationVsSimulation)). For AION 2 today, a sim would add scatter without fixing the center.

## Rankings survive wrong DPS only when the winner is clearly ahead

Absolute DPS can be wrong without harming comparisons, but only some errors are harmless. A shared scale error, such as dummy resistance applied equally to both options, never changes the order. A plain upgrade also survives any coefficient error. Trades between stats are the weak spot. A 100,000-trial test run for this research, a linear model with independent per-stat errors, gave these chances of ranking two options correctly:

| Trade | True gap | 5% stat error | 10% | 20% | 30% |
|---|---|---|---|---|---|
| Moves 2% of DPS | 0.5% | 99.9% | 94.3% | 78.3% | 70.1% |
| | 1% | 100% | 99.8% | 92.4% | 82.9% |
| Moves 5% of DPS | 0.5% | 91.0% | 75.0% | 63.1% | 58.9% |
| | 1% | 99.5% | 90.3% | 74.0% | 66.7% |
| | 2% | 100% | 99.1% | 88.3% | 78.4% |

Recomputing these cells shows they follow a simpler rule than the research note's linear approximation: reliability depends on **the ratio between what each option's stat contributes**, not on the absolute DPS gap. For 95% confidence, the winner's contribution must exceed the loser's by about 12% at 5% stat error, 26% at 10% and 59% at 20%. In a 5% trade at 20% error, that means a gap of about 3%, not the 2.3% the linear shortcut gives. The disputed stats above disagree by 30% to a factor of two, so they currently sit beyond the table's right-hand columns. Those are the stats the Global calibration should target first.

This test understates a third error type. Additive versus multiplicative buckets, caps and Combat Speed steps change the marginal values themselves, so they can flip a ranking regardless of coefficient quality. Variance also needs putting in proportion. Separating a 1% gap takes only about 50–770 iterations per option at per-fight variation of 2.5–10%, and 0.1% takes about 4,800–77,000 (own calculation, with roughly 50% power at exactly that gap). Going below 0.2–0.5% sampling error is wasted while the model is only good to about 1%. Raidbots' informal figure of 0.1–0.5% for small WoW choices ([Raidbots](https://support.raidbots.com/article/64-why-do-gem-enchant-sims-take-so-long)) warns that small choices may land inside the error band. AION 2's own gaps are unmeasured, so the tool should label such options "about equal" and re-rank with perturbed coefficients to show how stable each win is.

## Weekly patches, blocked imports and NC's stance shape the product

Upkeep is frequent but partly automatable. KR changed class skills in about 31 of 57 listed notes, across about 27 of 47 weeks, and this count from one-line blurbs likely undercounts ([AION2 Hub](https://aion2hub.com/updates)). Global has already changed cooldowns and bosses within a month: on 28 Oct it cut Assassin's Illusion Clone from 90 s to 60 s and reduced Transcendence level 1–2 boss HP by 6.5% ([mein-mmo](https://mein-mmo.de/en/aion-2-server-down-all-about-the-server-maintenance-and-the-patch-notes-on-october-28-2026-in-the-live-ticker,1593868/)). Diffing stamped JSON each week is cheap. Structural changes are not: KR's PvE/PvP damage split, and its 26 Aug pass of about 70 skill entries by a summariser's count, would need hand work and retesting ([AION2 Hub](https://aion2hub.com/updates/aion-2-update-2026-08-26)). Season 1 ends on 16 Dec 2026 ([MetaBot](https://metabot.gg/en/aion-2)), which makes a natural re-validation point.

Character import needs a server. The official routes are undocumented and return stats, gear and Daevanion boards, but a browser cannot read them from GitHub Pages, and every project found uses a proxy ([AION-2-Character-Check](https://github.com/nklsgod/AION-2-Character-Check)). NC reportedly removed the Item route from Global around 12 Oct, a further sign of fragility ([nuriland/aion2-api](https://github.com/nuriland/aion2-api)). A Supabase Edge Function could technically do this, but the origin rejection looks deliberate and NC's terms on automated access were not read. Manual entry plus screenshot reading, already used by the planner's Game Check and the Pets importer, is the safer default, though no Ctrl+X reader has been prototyped.

Policy risk depends on the data, not on the math. No official statement names DPS meters as allowed or banned, and no meter-specific ban was documented, though that absence proves little ([Metaroad](https://metaroad.gg/aion2/getting-started/aion-2-tools-korean-community-uses)). A website that takes manual input or a user's own Ctrl+X screenshots looks well outside the unauthorized-program clause. This is an inference from the Korean service's policy, not legal advice, and the Global terms were not read. The danger grows with named damage records, leaderboards, and bundling or promoting packet meters. The tool should therefore stay own-character only and link to no meter. Reuse is a separate question: Aion2Data allows reading and quoting with a link, but that does not clearly cover bulk redistribution ([llms.txt](https://aion2data.com/llms.txt)), and its data has not been checked against the game. GPL-licensed meter data cannot be copied without taking on GPL obligations.

The category is contested. STIGMA lists a DPS simulator, stat weights and item comparison, with no stated inputs or validation ([STIGMA](https://stigma.pro/tools)). AION2 Atlas estimates rotations from manually entered skill values and calls its 1.5× crit "not confirmed" ([AION2 Atlas](https://aion2atlas.app/dps-meter/)). RATmeter has a stat-efficiency calculator ([RATmeter](https://github.com/Kuroukihime/AIon2-Dps-Meter)), and a KR calculator covers breakpoints and party buffs while excluding skill coefficients ([calculator](https://bongbong99999-debug.github.io/aion2ssow/)). **No tool found publicly documents validation against real combat data.** Their accuracy is unknown rather than known to be poor, and STIGMA's simulator was not opened. No public theorycraft sheet surfaced either, though Discord and private sheets could not be searched, and the "A2Viewer" name could not be found.

The validation route itself is low-risk. Fan guides describe a built-in Combat Analysis window (Ctrl+X) showing per-skill damage, hits and crit rate, with level-matched, infinite-health dummies ([AION2 Atlas](https://aion2atlas.app/dps-meter/), [Destructoid](https://www.destructoid.com/all-training-dummy-locations-in-aion-2/)). No NC manual was read and per-skill crit detail varies by guide, so this needs a quick in-game check. It avoids the roughly 2% disagreement reported between meters, in a single user post ([Inven](https://www.inven.co.kr/board/aion2/6388/104374)).

## Conclusion

### Feasibility verdict

**Feasible in tiers: yes for a calibrated comparison tool, conditional for one-class rotation sims, no for a Raidbots equivalent at present.** The stack fits every tier that does not need a server. Accuracy and upkeep, not hosting, set the ceiling. This is a shift from how the question usually frames itself: the choice is less "formula or sim" than which player decisions the evidence can support, and the tool can state that per comparison.

### What could be built

| Tier | What it answers | Works on static SPA? | Evidence today | Verdict |
|---|---|---|---|---|
| **1. Stat-efficiency calculator** | Marginal value of each stat at my current stats | Yes | Skeleton tested on KR/TW; Global constants unverified | Buildable now, but competitors already offer it and it adds little alone |
| **2. Calibrated gear and Daevanion comparer** | Is A better than B, and is the win stable? Uses a fixed skill mix, expected damage, ties and perturbation | Yes, in workers, with build-time data | Inputs ready; needs one-class Global calibration; Combat Speed handled through measured breakpoints or a warning | **Recommended target** |
| **3. Dummy rotation sim, one or two classes** | Does this rotation or Combat Speed value change the answer? | Yes; compute looks adequate | Timing, cancels, procs and latency unmeasured | Conditional on timing tests, per class |
| **4. Raidbots-style service** | Top Gear for all 8 classes on real bosses, with armory import | No, import needs a proxy | Boss defense unknown; hand-written logic per class; weekly patches | Not feasible now; revisit if NC ships an official API or a maintainer community forms |

### Main blockers

| Blocker | Severity | Mitigation |
|---|---|---|
| Timing unknown: cancels, Combat Speed steps, latency, procs | Blocks Tier 3 and limits Tier 2 | Measure per class; flag Combat Speed trades as unverified until then |
| No official formula and no readable Global replication | High | Calibrate on Global; publish results and tolerance by build |
| Boss HP, defense and resistance are server-side | Blocks realistic boss presets | Dummy scenario first; user-set resistance and uptime; label measured values by build |
| Weekly patches, with occasional structural changes | High recurring cost | Snapshot and diff stamped JSON; show data build; warn when stale |
| One maintainer against 8 classes | High for Tiers 3–4 | Ship class by class; do not list a class until it passes validation |
| Single-operator data source with unclear bulk-reuse terms | Medium | Ask Aion2Data; use build-time snapshots; spot-check values in game |
| No browser-readable character import | Medium; convenience only | Manual and screenshot input; proxy only after reading NC's terms |
| NC's stance on third-party data | Low for own-character math, high for leaderboards or meter promotion | Own-character only; no shared records |

Browser performance does not belong on this list. It still deserves a benchmark on a phone and Safari if Tier 3 goes ahead.

### Recommended first step

**Run a one-class Global calibration before writing any UI.** Choose a class you play, and write a Node script in the style of `scripts/buildPetAtlas.ts` that snapshots Aion2Data skills and predicts per-skill damage from the community formula. Then measure about 10 skills on a Global dummy, using Ctrl+X where it suffices. Korean and Taiwanese tests found damage rolls come only from the weapon range and that skills still deal fixed damage with no weapon ([Inven 902](https://www.inven.co.kr/board/aion2/6444/902)), so weaponless runs should give clean, deterministic readings if that holds on Global. Fit one shared scale for dummy defense and resistance, then change one stat at a time, starting with multi-hit, Perfect and Weapon Damage Boost. Crit rate needs volume: about 1,000 hits for ±3 points at a 50% rate, so the 100-hit samples in existing tests carry about ±10 points.

I propose this pass bar, which is a judgment call and not an established standard: non-crit predictions within about 2% across skills after the shared fit, and single-stat changes matching measured direction and size within the noise. A pass funds Tier 2. For Tier 3, add a second gate: predict cast counts in a fixed 180-second run at two Combat Speed values within about 2%. If skills cannot be fitted with one shared scale, the formula is structurally wrong on Global and the published model should not be shipped as a ranking tool. Alongside this, spend an hour on three cheap checks: confirm Ctrl+X's fields in game, open STIGMA's simulator, and ask Aion2Data's operator about snapshot reuse. The output is useful even if the project stops there, since it would be the first public Global validation this research could find.
